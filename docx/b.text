PROJECT NAME:
AI Urban Farming Assistant

PROJECT OBJECTIVE:
Build a complete backend for an AI-powered urban gardening application. Users must be able to register plants, upload leaf images, identify possible plant diseases, receive treatment recommendations, obtain personalized watering guidance based on plant conditions and weather, and track plant health over time.

The backend must support this complete demo:
1. Create or select a user.
2. Add a tomato plant.
3. Upload a tomato leaf image.
4. Validate and securely store the image.
5. Run an actual plant disease classification model.
6. Return the predicted class, model confidence, and uncertainty status.
7. Return relevant disease symptoms and basic care recommendations.
8. Generate watering guidance based on plant details, soil condition, and weather.
9. Save the diagnosis and care activities.
10. Return updated plant information and health history to the frontend.

YOUR ROLE:
Think like a senior backend engineer. Build a working, modular backend, not a collection of disconnected endpoints. Follow separation of concerns, SOLID principles where appropriate, clear data contracts, robust error handling, security best practices, testability, and maintainable code.

Do not stop at architecture documentation or pseudocode. Inspect the existing repository and implement the actual backend.

6. WATERING RECOMMENDATION ENGINE
Implement a deterministic, explainable rule-based watering engine for the POC.

Inputs:
- plant species
- growth stage
- pot size
- growing location
- sunlight hours
- drainage quality
- soil condition
- temperature
- humidity
- rainfall forecast
- forecast period
- optional soil moisture sensor reading

Soil condition enum:
- wet
- moist
- slightly_dry
- dry
- unknown

Recommendation output:
- recommendation_id
- plant_id
- action
- summary
- explanation
- urgency
- suggested_recheck_at
- input_conditions
- created_at

Actions:
- water_consider
- check_soil
- wait_and_reassess
- check_drainage
- insufficient_information

Business rules:
- Wet soil: do not recommend additional watering solely based on temperature.
- Moist soil: usually wait and reassess.
- Dry root zone: consider watering according to crop and growth stage.
- Hot or sunny weather: may increase soil-check frequency.
- Rain forecast: account for actual rainfall, outdoor exposure, and soil moisture.
- Poor drainage: warn about waterlogging risk.
- Unknown soil condition: ask the user to inspect soil or provide sensor data.
- Do not equate humidity with soil moisture.
- Do not present forecast-based estimates as measured soil conditions.

Create a WateringRecommendationService with separately testable rule functions.

Endpoints:
POST /api/v1/plants/{plant_id}/care/watering-recommendation
GET /api/v1/plants/{plant_id}/care
GET /api/v1/plants/{plant_id}/care/watering-recommendations

Persist recommendation history where useful. Clearly distinguish a generated recommendation from a completed watering event.
